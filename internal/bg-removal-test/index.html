Client-side background removal — feasibility test

Internal test page — not linked, not indexed, not production. Evaluating @imgly/background-removal (ONNX model via onnxruntime-web, runs entirely in-browser) as a possible "plain white background" step for the face-photo editor. Nothing here is wired into the real upload flow — this page exists to measure real download size / processing time / memory use before we decide anything. See the network note at the bottom for exactly what this page fetches and why.

What this page sends over the network

On your first click of "Remove background", this page loads @imgly/background-removal and onnxruntime-web as ES modules (via an import map, from jsDelivr), which in turn fetch the ONNX segmentation model weights and onnxruntime's own WASM runtime binary — by default from IMG.LY's own CDN (staticimgly.com). Those are one-way downloads of model/runtime files, the same every time, containing no data from you. After that one-time load (cached by the browser + an additional model cache the library manages itself), the actual background removal runs locally via WASM/WebGPU: nothing in this page's code sends the uploaded photo, the cutout, or any result anywhere. This page requests cross-origin-isolation headers (COOP/COEP, scoped to just this one route via _headers) so the library can use SharedArrayBuffer-based multi-threading if the browser allows it — that's a performance option, not a data-sharing one.
